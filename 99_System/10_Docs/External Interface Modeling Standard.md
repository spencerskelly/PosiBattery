# External Interface Modeling Standard

## Concrete-first rule

External ecosystem modeling begins with observed facts, not an abstract integration taxonomy.

For each interaction:
1. identify the exact endpoint on each side;
2. record the named Interface or interaction surface;
3. create separate directional Item Flows for each verified exchange;
4. record mechanism/protocol only when supported by evidence;
5. preserve unknown directions, fields, lifecycle/status behavior, and error paths as unknown;
6. repeat across products/systems;
7. generalize only after multiple concrete examples demonstrate stable shared semantics.

Two interfaces may share a business label without sharing schemas, timing, ownership, operations, or error behavior.
