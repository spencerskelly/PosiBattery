# Engineer Quick Start

## 1. Open the vault

Open this folder directly in Obsidian. If prompted, trust/enable community plugins. The MDSE Bootstrap plugin verifies the pinned plugin stack.

## 2. Reload once

After the first open or after pulling a large Git change, reload Obsidian once. This allows Nodian/Breadcrumbs/bootstrap relationship synchronization to initialize cleanly.

## 3. Read the governing rules

Start with:
1. [[99_System/10_Docs/MDSE Modeling Ruleset 1.18]]
2. [[99_System/10_Docs/MDSE Metamodel]]
3. [[99_System/10_Docs/Relationship Ownership]]
4. [[99_System/10_Docs/Model Evidence and Acceptance Standard]]
5. [[99_System/02_AI/AI_INSTRUCTIONS]]

## 4. Review the generic examples

Open [[98_Examples/README]]. These notes demonstrate mechanics only and can be deleted when the project starts.

## 5. Start from evidence

Do not begin by filling every folder. Inventory what is known, what is assumed, and what is missing.

## 6. Use AI carefully

For an AI-assisted first pass, follow [[99_System/02_AI/AI Model Kickoff Workflow]]. Keep drafts in `90_Concept/AI_Workspace` until team review.

## 7. Check model health

Use:
- [[99_System/07_Views/Model Health]]
- [[99_System/07_Views/Requirement Traceability]]
- [[99_System/07_Views/Verification Coverage]]
- Breadcrumbs Trail/Tree/Matrix for relationships.

## 8. Keep navigation healthy

Immediate model folders should remain under 25 modeled elements. Split only on real semantic distinctions and give every new model-facing folder its guide/Base/Canvas package.
